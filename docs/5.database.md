# 5. Database Design — Firestore + SQLite

## 1. Which store for what (and why)

| Data | Store | Why |
|---|---|---|
| User profiles, belts, streaks, weak tactics | **Firestore** | Per-user, mutable, must persist across Cloud Run instances and deploys; auth-linked |
| Train sessions (transcripts, assessments, debriefs, scores) | **Firestore** | Same; documents are naturally nested |
| Check history, Recovery plans, step states, chats | **Firestore** | Same |
| Usage counters, global impact counters | **Firestore** | Transactional increments; shared across instances |
| Scenarios, scam types, tactics, red flags, helplines/resources, regex rules, KB articles | **SQLite `knowledge.sqlite`** (read-only, baked into the image) | Static, relational, searchable (FTS5), versioned with code, deterministic in tests, no network hop, works offline. A cloud DB adds cost/latency/failure modes with no benefit |
| Demo response cache, per-instance rate-limit buckets | **SQLite in `/tmp`** | Ephemeral by design; speeds up and de-risks the live demo. Cloud Run's filesystem is not durable, so **nothing important is written to SQLite in production** |
| Local dev/test persistence | **SQLite (`dojo.sqlite`) via `SqliteRepo`** | Run the full stack without GCP; fast tests |

Region: create Firestore in **`asia-south1` (Mumbai)** (cannot be changed later). Mode: **Native**.

## 2. Firestore schema

All writes happen server-side through the Admin SDK. Client SDK has read access only to the user's own documents (and in v1 the web app doesn't read Firestore directly at all).

### 2.1 `users/{uid}`
```jsonc
{
  "displayName": "Asha",              // from Google; null for guests
  "photoURL": null,
  "isAnonymous": true,
  "language": "en",                   // "en" | "hi"
  "timezone": "Asia/Kolkata",
  "createdAt": "<timestamp>", "lastActiveAt": "<timestamp>",
  "resilience": 0,                    // 0–100 current Resilience Score
  "belt": "white",                    // derived, stored for cheap reads
  "sessionsCompleted": 0,
  "scenariosCompleted": { "fake_kyc": {"count": 2, "bestScore": 81, "maxDifficulty": 3} },
  "streak": { "current": 0, "best": 0, "lastActiveDate": "2026-10-14" },
  "weakTactics": { "urgency": 0.0, "authority": 0.0, "fear": 0.0, "greed": 0.0, "trust": 0.0, "isolation": 0.0 },
  "recentScamTypes": ["kyc_fraud"],   // last 5 from Check/Recover (for personalisation)
  "recommendedDifficulty": 1,
  "counts": { "train": 0, "check": 0, "recover": 0 },
  "scoreHistory": [ { "date": "2026-10-14", "score": 62, "resilience": 55, "sessionId": "…" } ],  // capped to last 50
  "settings": { "hideHints": false, "traceDefault": false }
}
```
`scoreHistory` is denormalised on the profile so the dashboard needs **one read**.

### 2.2 `users/{uid}/trainSessions/{sid}`
```jsonc

  "language": "en", "difficulty": 3, "difficultyMode": "auto",
  "status": "active",                 // active | ended
  "outcome": null,                    // user_won | user_fell | walked_away | max_turns

  "turnCount": 0, "stage": "hook", "tension": 2, "safetyBreak": false,
  "messages": [                       // scrubbed text only
    { "i": 0, "role": "scammer", "text": "…", "ts": "<ts>" },
    { "i": 1, "role": "user", "text": "which bank?", "ts": "<ts>", "clientMsgId": "uuid", "pii": [] },
    { "i": 2, "role": "scammer", "text": "…", "ts": "<ts>", "partial": false }
  ],
  "assessments": [ { "turn": 1, "...": "TurnAssessment fields + tacticUsedByScammer" } ],
  "score": { "outcomePoints": 0, "flagPoints": 0, "verifyPoints": 0, "dataPoints": 0, "coachAdj": 0, "final": 0, "resilienceBefore": 0, "resilienceAfter": 0, "beltBefore": "white", "beltAfter": "white" },

  "model": { "fast": "…", "lite": "…", "pro": "…" }   // what actually ran (for reproducibility)

```
Size note: ≤ 14 user turns ⇒ < 50 KB per doc; far below the 1 MB limit. If you later raise `max_turns`, move `messages` to a subcollection.


### 2.5 `users/{uid}/customScenarios/{id}`
`ScenarioSpec` (same shape as built-in) + `{ createdAt, sourceCheckId, custom: true }`.

### 2.6 `usage/{uid}_{YYYYMMDD}`
`{ uid, date, trainTurns, checks, recoverCalls, updatedAt }` — TTL policy on `expireAt` (now + 3 days).

### 2.7 `stats/global`
`{ trainSessions, checks, recoveryPlans, redFlagsSurfaced, updatedAt }` incremented with `FieldValue.increment`. Exposed via `GET /v1/stats/global` (cached 60s) for the landing/pitch ("12,431 practice moves so far"). **Only show real counters.**

### 2.8 Indexes (`firebase/firestore.indexes.json`)
- `trainSessions`: `(status ASC, startedAt DESC)` · `(startedAt DESC)` (single-field default is enough for the latter).
- `checks`: `(createdAt DESC)` · `recoveries`: `(updatedAt DESC)`.
Collection-group indexes are not needed in v1.

### 2.9 Security rules (`firebase/firestore.rules`)
```
rules_version = '2';
service cloud.firestore {
  match /databases/{db}/documents {
    // Clients may only read their own data. All writes go through the backend (Admin SDK bypasses rules).
    match /users/{uid} {
      allow read: if request.auth != null && request.auth.uid == uid;
      allow write: if false;
      match /{document=**} {
        allow read: if request.auth != null && request.auth.uid == uid;
        allow write: if false;
      }
    }
    match /usage/{doc}  { allow read, write: if false; }
    match /stats/{doc}  { allow read: if true; allow write: if false; }   // aggregate counters only
    match /{document=**} { allow read, write: if false; }
  }
}
```
Add a rules unit test with the Firebase emulator (`@firebase/rules-unit-testing`).

### 2.10 Transactions that must be atomic
1. **Finish a train session:** update session (`status`, `outcome`, `score`, `debrief`) + user (`resilience`, `belt`, `streak`, `weakTactics`, `scoreHistory` push/cap, `scenariosCompleted`, `counts.train`) + `stats/global` increment.
2. **Append turn:** session `messages` (`arrayUnion` is not safe for duplicates with timestamps — use read-modify-write in a transaction keyed by `turnCount`, reject if `turnCount` mismatch → idempotency with `clientMsgId`).
3. **Usage increment:** transaction with limit check.

## 3. SQLite — `knowledge.sqlite` (read-only at runtime)

Built by `scripts/build_kb.py` from `data/seed/*.yaml`; schema versioned with `PRAGMA user_version`. `make kb` must be deterministic (sorted inserts) so diffs are reviewable. CI fails if the DB is out of date with the seeds.

```sql
PRAGMA journal_mode = OFF;  -- build-time only; opened read-only at runtime
PRAGMA user_version = 1;

CREATE TABLE meta (key TEXT PRIMARY KEY, value TEXT);   -- built_at, seed_hash, schema_version

CREATE TABLE scam_types (
  id INTEGER PRIMARY KEY, slug TEXT UNIQUE NOT NULL,
  name_en TEXT NOT NULL, name_hi TEXT NOT NULL,
  summary_en TEXT NOT NULL, summary_hi TEXT NOT NULL,
  typical_channels TEXT NOT NULL,           -- JSON array
  severity INTEGER NOT NULL CHECK (severity BETWEEN 1 AND 5)
);

CREATE TABLE tactics (
  id INTEGER PRIMARY KEY, slug TEXT UNIQUE NOT NULL,      -- urgency|authority|fear|greed|trust|isolation
  name_en TEXT NOT NULL, name_hi TEXT NOT NULL,
  description_en TEXT NOT NULL, description_hi TEXT NOT NULL,
  counter_tip_en TEXT NOT NULL, counter_tip_hi TEXT NOT NULL
);

CREATE TABLE red_flags (
  id INTEGER PRIMARY KEY, scam_type_id INTEGER REFERENCES scam_types(id),
  tactic_slug TEXT REFERENCES tactics(slug),
  text_en TEXT NOT NULL, text_hi TEXT NOT NULL, weight INTEGER NOT NULL DEFAULT 1
);

CREATE TABLE scenarios (
  id INTEGER PRIMARY KEY, slug TEXT UNIQUE NOT NULL,
  scam_type_slug TEXT NOT NULL REFERENCES scam_types(slug),
  channel TEXT NOT NULL, min_belt TEXT NOT NULL DEFAULT 'white',
  difficulty_min INTEGER NOT NULL, difficulty_max INTEGER NOT NULL,
  est_minutes INTEGER NOT NULL, active INTEGER NOT NULL DEFAULT 1,
  title_en TEXT NOT NULL, title_hi TEXT NOT NULL,
  blurb_en TEXT NOT NULL, blurb_hi TEXT NOT NULL,
  spec_json TEXT NOT NULL                     -- full scenario YAML as JSON (see 4.agents.md §3.1)
);

CREATE TABLE resources (
  id TEXT PRIMARY KEY,                         -- stable slug e.g. 'r_1930'
  country TEXT NOT NULL DEFAULT 'IN',          -- ISO code
  category TEXT NOT NULL,                      -- helpline | portal | bank_guidance | identity | telecom | emotional_support | emergency
  name_en TEXT NOT NULL, name_hi TEXT NOT NULL,
  contact_type TEXT NOT NULL,                  -- phone | url | none
  contact_value TEXT,                          -- '1930' or 'https://…'
  description_en TEXT NOT NULL, description_hi TEXT NOT NULL,
  when_to_use_en TEXT NOT NULL, when_to_use_hi TEXT NOT NULL,
  triggers_json TEXT NOT NULL,                 -- JSON: rules for resource_selector (incident types, money_lost, time windows)
  priority INTEGER NOT NULL DEFAULT 50,        -- lower = shown earlier
  source_url TEXT NOT NULL,                    -- official page used to verify
  verified_on TEXT,                            -- ISO date; NULL = unverified (CI warns; must be set before release)
  active INTEGER NOT NULL DEFAULT 1
);

CREATE TABLE pattern_rules (
  id INTEGER PRIMARY KEY, kind TEXT NOT NULL,   -- shortener | suspicious_tld | keyword | brand_lookalike | remote_app | ...
  lang TEXT NOT NULL DEFAULT 'any',             -- en | hi | hinglish | any
  pattern TEXT NOT NULL,                        -- regex (Python re, case-insensitive)
  tag TEXT NOT NULL,                            -- e.g. urgency, otp_request, threat, prize, kyc, remote_app, safe_account
  weight INTEGER NOT NULL DEFAULT 1, note TEXT
);

CREATE TABLE known_brands (                     -- for lookalike-domain checks (names only, no logos)
  id INTEGER PRIMARY KEY, name TEXT NOT NULL, domains_json TEXT NOT NULL, kind TEXT NOT NULL   -- bank | wallet | courier | govt | telecom | ecommerce
);

CREATE TABLE kb_docs (                          -- RAG-lite playbooks (short, factual)
  id INTEGER PRIMARY KEY, slug TEXT UNIQUE NOT NULL, lang TEXT NOT NULL,
  scam_type_slug TEXT, title TEXT NOT NULL, body TEXT NOT NULL, source_url TEXT
);
CREATE VIRTUAL TABLE kb_fts USING fts5(title, body, scam_type_slug UNINDEXED, lang UNINDEXED, content='kb_docs', content_rowid='id', tokenize='unicode61 remove_diacritics 2');
-- populate with INSERT INTO kb_fts(kb_fts) VALUES('rebuild') after loading kb_docs

CREATE INDEX idx_resources_cat ON resources(category, active, priority);
CREATE INDEX idx_rules_kind ON pattern_rules(kind, lang);
```

### Seed files (`data/seed/`)
`scam_types.yaml` · `tactics.yaml` · `red_flags.yaml` · `scenarios/*.yaml` (4 files) · `resources.yaml` · `pattern_rules.yaml` · `known_brands.yaml` · `kb/*.md` (front-matter: slug, lang, scam_type, source_url; ≥ 12 docs covering UPI collect/refund, KYC/SMS phishing, job/task scams, digital arrest/impersonation, investment/stock groups, loan-app harassment, courier/customs, electricity/utility disconnection, fake customer-care numbers, QR-code scams, lottery/prize, romance/sextortion — written in your own words, ≈ 150–300 words each, EN + HI where possible).

**Known-brand list rule:** names/domains of real banks and services are acceptable here for *detection* only (never emitted by the Scammer agent). Keep to publicly documented official domains.

## 4. SQLite — runtime cache (`/tmp/dojo_cache.sqlite`, ephemeral)
```sql
CREATE TABLE IF NOT EXISTS response_cache (key TEXT PRIMARY KEY, kind TEXT, payload TEXT NOT NULL, created_at INTEGER NOT NULL);
CREATE TABLE IF NOT EXISTS rate_bucket (k TEXT PRIMARY KEY, tokens REAL NOT NULL, ts REAL NOT NULL);
```
`PRAGMA journal_mode=WAL; PRAGMA synchronous=NORMAL;`. Treat as a cache: any read may miss. Purge entries older than 7 days at startup.

## 5. SQLite — local repo (`SqliteRepo`, dev/test only)
Mirror the Firestore collections as tables with JSON columns:
```sql
CREATE TABLE users (uid TEXT PRIMARY KEY, doc TEXT NOT NULL);
CREATE TABLE train_sessions (uid TEXT, sid TEXT, started_at TEXT, doc TEXT, PRIMARY KEY (uid, sid));
CREATE TABLE checks (uid TEXT, cid TEXT, created_at TEXT, doc TEXT, PRIMARY KEY (uid, cid));
CREATE TABLE recoveries (uid TEXT, pid TEXT, updated_at TEXT, doc TEXT, PRIMARY KEY (uid, pid));
CREATE TABLE custom_scenarios (uid TEXT, id TEXT, doc TEXT, PRIMARY KEY (uid, id));
CREATE TABLE usage (k TEXT PRIMARY KEY, doc TEXT);
CREATE TABLE global_stats (k TEXT PRIMARY KEY, v INTEGER NOT NULL DEFAULT 0);
```
Use SQLite transactions for the atomic operations in §2.10. `STORE=sqlite` is **forbidden in prod** (enforced by config).

## 6. Data lifecycle
- Retention: Train/Check/Recover docs kept until the user deletes them; anonymous accounts inactive > 90 days are purged by a scheduled Cloud Run job / Cloud Scheduler (SHOULD) using `lastActiveAt`.
- Deletion: `DELETE /v1/me/data` removes subcollections (batched recursive delete) and the profile; also delete the Firebase Auth user when requested from Settings ("Delete account").
- Backups: Firestore scheduled daily backup (optional) — not required for the hackathon.
- Export: `GET /v1/me/export` returns the user's JSON.
