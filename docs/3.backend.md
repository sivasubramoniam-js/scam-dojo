# 3. Backend — Engineering Spec

FastAPI service on Cloud Run orchestrating Google ADK agents (spec in `4.agents.md`), persisting to Firestore (prod) or SQLite (local), grounded on `knowledge.sqlite` (`5.database.md`). Request/response shapes: `6.api-contract.md`.

---

## 1. Stack

| Concern | Choice |
|---|---|
| Language | Python 3.12 |
| Web | FastAPI + Uvicorn (`--workers 1`; concurrency via async), `sse-starlette` or hand-rolled `StreamingResponse` |
| Agents | `google-adk`, `google-genai` (verify latest versions; pin in `requirements.lock`) |
| Models | Vertex AI Gemini in prod via ADC; AI Studio key locally (see §3) |
| Data | `google-cloud-firestore` (async client), `sqlite3` (stdlib, read-only for KB), `aiosqlite` for local repo |
| Auth | `firebase-admin` (verify ID tokens) |
| Validation | Pydantic v2 (all I/O and all LLM structured outputs) |
| Templating | Jinja2 for prompts (avoids ADK `{}` state templating collisions) |
| Resilience | `tenacity` (retries w/ jitter), request timeouts, circuit-breaker light (fail-fast after N consecutive model errors for 30s) |
| Logging | `structlog` JSON → Cloud Logging (`severity`, `trace`, `request_id`, `uid_hash`) |
| Tooling | `uv` or pip-tools, `ruff`, `mypy --strict` on `app/`, `pytest`, `pytest-asyncio`, `httpx` |

## 4. Request pipeline

1. **Middleware:** request ID (`X-Request-ID` echo), structured access log, CORS allow-list, security headers (`X-Content-Type-Options`, `Referrer-Policy`, `Cache-Control: no-store` for API).
2. **Auth dependency:** `Authorization: Bearer <Firebase ID token>` → `firebase_admin.auth.verify_id_token` (cache JWKs, check `aud`/`iss`). Produces `User{uid, is_anonymous, email?}`. Dev mode: `X-Dev-User: alice` → `uid="dev-alice"`.
3. **Language dependency:** `Accept-Language` / `lang` query / profile fallback → `Literal['en','hi']` (extensible).
4. **Quota dependency** per router (see §7).
5. **Router → service/agent → repo.**
6. **Errors** converted to the envelope in the API contract (`code`, `message`, `retryable`, `request_id`).

### Streaming responses
- `Content-Type: text/event-stream; charset=utf-8`, headers `Cache-Control: no-cache, no-transform`, `X-Accel-Buffering: no`, `Connection: keep-alive`.
- Send a comment heartbeat (`: ping\n\n`) every 15s to keep proxies alive.
- Each event: `event: <name>\ndata: <json>\n\n`. Always finish with `event: done`.
- Support `?stream=false` on every streaming endpoint: collect and return a single JSON (used as client fallback and in tests).
- On client disconnect (`request.is_disconnected()`), cancel the agent run; **persist whatever was completed** (e.g. user message + partial assistant message flagged `partial=true`).

## 5. Services

### 5.1 PII scrubber (`services/scrubber.py`) — authoritative
`scrub(text, *, mode) -> ScrubResult{text, found: list[PiiType], redactions: int}` using the same pattern set as frontend §6 (Aadhaar with Verhoeff-valid check optional, PAN, Luhn card, mobile, UPI id, email, OTP/PIN/CVV by context keywords in EN + Hindi + Hinglish: `otp, code, pin, cvv, ओटीपी, पिन, कोड`).
- `mode='train'`: replace with typed placeholders `[AADHAAR] [PAN] [CARD] [PHONE] [UPI] [OTP] [PIN] [CVV]`. `found` is passed to the Observer as ground truth for `leaked_data_types`.
- `mode='store'` (Check/Recover previews): redact all of the above and emails; truncate preview to 500 chars.
- Unit tests: ≥ 40 cases including false positives (order numbers, years, amounts like "₹2,000") and Devanagari digits (normalise `०-९` → `0-9` before matching).

### 5.2 Knowledge base (`services/kb.py`)
Opens `KB_PATH` read-only (`file:...?mode=ro`, `uri=True`), one connection per thread/loop. Methods:
- `scenarios(lang, belt)`, `scenario(slug)`
- `resources(country='IN', category=None, lang)`; `resource_by_ids(ids)`
- `search_kb(query, lang, k=5)` → FTS5 `bm25` ranked snippets (title, body, scam_type)
- `pattern_rules()` → compiled regexes for the Indicator agent
- `tactics()`, `scam_types()`
Cache results in-process (`functools.lru_cache`); KB is immutable at runtime.

### 5.3 Web Risk (`services/webrisk.py`, optional)
If `WEBRISK_ENABLED`: call Google **Web Risk** `uris.search` for each extracted URL (threat types: `MALWARE`, `SOCIAL_ENGINEERING`, `UNWANTED_SOFTWARE`) with 2s timeout; failures are silent (return `unknown`). Results become `indicators.url_reputation[]`. Never block the pipeline on it.

### 5.4 Safety (`services/safety.py`)
- **Distress detector** (Train): regex + small Lite-model classification on user turns for phrases like "I actually sent money", "this is real", "I'm scared", Hindi equivalents → sets `state.safety_break=true` → Scammer prompt emits `[Sensei]` break; frontend shows an inline card linking to Recover mode.
- **Output filter** (Train scammer output): reject/replace if it contains a real-looking phone number (`+91` followed by non-placeholder digits), URL not ending in `.example`, UPI ID not ending in `@fakebank`/`@oksim` (use `@fakebank` only), or the words "I am an AI", "simulation" (outside Sensei break). On violation: regenerate once with a stricter reminder; if still failing, send a neutral fallback line from the scenario's `fallback_lines`.
- **Prompt-injection heuristics** (Check/Recover): flag strings like "ignore previous", "system prompt", "you are now"; they are *still analysed as scam content* but recorded as an indicator (`prompt_injection_attempt`).
- Gemini `safety_settings` kept at defaults except `HARM_CATEGORY_DANGEROUS_CONTENT` and `HARASSMENT` at `BLOCK_ONLY_HIGH` for the Scammer to avoid false blocks on roleplay; log all blocks.

### 5.5 Media (`services/media.py`)
- Accept: images (png/jpeg/webp ≤ 10MB), video (mp4/webm ≤ 20MB; duration ≤ 30s — check with `ffprobe` if available, else trust client + size), audio (mp3/m4a/wav/ogg/webm ≤ 10MB, ≤ 2 min).
- Validate **magic bytes**, not just the `Content-Type`. Strip EXIF from images before sending to the model.
- Max 3 files per request. Files are held **in memory only**, never written to disk or Cloud Storage; persist only `{type, size, sha256}` metadata.
- Inline `Part.from_bytes` when total ≤ 20MB.

### 5.6 Quota (`services/quota.py`)
- Daily per-user counters in repo (`usage/{uid}_{YYYYMMDD}`) incremented transactionally; limits from config.
- In-memory token bucket per `uid` + per IP for burst (e.g. 20 req/10s) — per-instance and approximate by design.
- On exceed → `429 rate_limited` with `retry_after` and localized message key.

### 5.7 Cache (`services/cache.py`, demo mode)
`/tmp` SQLite `response_cache(key TEXT PRIMARY KEY, payload TEXT, created_at INT)`; key = `sha256(kind|lang|model|normalised_input)`. Used for: Check verdicts (when `DEMO_MODE=cached|record`), scenario opening lines, debrief for scripted demo runs. See §9.

## 6. Repository layer (`repo/base.py`)

A `Protocol` implemented by `FirestoreRepo` and `SqliteRepo` (same behaviour, tested by the same contract tests parametrised over both; Firestore tested against the **emulator** in CI optionally).

```python
class Repo(Protocol):
    # profile
    async def get_or_create_user(self, uid: str, defaults: dict) -> UserDoc: ...
    async def update_user(self, uid: str, patch: dict) -> UserDoc: ...
    async def delete_user_data(self, uid: str) -> None: ...
    async def export_user_data(self, uid: str) -> dict: ...
    # train
    async def create_train_session(self, uid: str, doc: TrainSessionDoc) -> str: ...
    async def get_train_session(self, uid: str, sid: str) -> TrainSessionDoc | None: ...
    async def append_train_turn(self, uid: str, sid: str, turn: TurnDoc, state_patch: dict) -> None: ...
    async def finish_train_session(self, uid: str, sid: str, patch: dict) -> None: ...
    async def list_train_sessions(self, uid: str, limit: int, cursor: str | None) -> list[TrainSessionDoc]: ...
    # check
    async def save_check(self, uid: str, doc: CheckDoc) -> str: ...
    async def get_check(self, uid: str, cid: str) -> CheckDoc | None: ...
    async def list_checks(self, uid: str, limit: int) -> list[CheckDoc]: ...
    # recover
    async def save_plan(self, uid: str, doc: RecoveryDoc) -> str: ...
    async def get_plan(self, uid: str, pid: str) -> RecoveryDoc | None: ...
    async def set_step_done(self, uid: str, pid: str, step_id: str, done: bool) -> None: ...
    async def append_plan_chat(self, uid: str, pid: str, msgs: list[dict]) -> None: ...
    async def list_plans(self, uid: str, limit: int) -> list[RecoveryDoc]: ...
    # forge
    async def save_custom_scenario(self, uid: str, spec: dict) -> str: ...
    async def get_custom_scenario(self, uid: str, scenario_id: str) -> dict | None: ...
    # usage + global
    async def incr_usage(self, uid: str, kind: str, n: int = 1) -> int: ...
    async def incr_global(self, field: str, n: int = 1) -> None: ...
    async def get_global(self) -> dict: ...
```
Firestore specifics in `5.database.md`. Use batched/transactional writes for turn appends and score updates (profile + session finish in one transaction).

## 7. Routers (summary; exact shapes in API contract)

- `health`: `GET /healthz` (liveness, no auth), `GET /readyz` (KB opens, repo ping, model config present).
- `me`: `GET /v1/me`, `PATCH /v1/me`, `DELETE /v1/me/data`, `GET /v1/me/export`.
- `scenarios`: `GET /v1/scenarios` (built-in + user's custom; lock state from belt).
- `train`: create session; send message (SSE); end/debrief; get; list.
- `check`: `POST /v1/check` (multipart, SSE); `GET /v1/checks`; `GET /v1/check/{cid}`; `POST /v1/check/{cid}/to-drill`.
- `recover`: create plan (SSE); get; step toggle; chat (SSE); list.
- `dashboard`: `GET /v1/dashboard`.
- `resources`: `GET /v1/resources`.
- `stats`: `GET /v1/stats/global` (public, cached 60s).

### Train endpoint orchestration (pseudocode)
```python
async def post_message(sid, body, user, repo, kb, req):
    sess = await repo.get_train_session(user.uid, sid)           # 404/409 if not active
    scrub = scrubber.scrub(body.text, mode='train')
    if body.client_msg_id in sess.seen_ids: return replay_cached(sess, body.client_msg_id)   # idempotency
    state = build_state(sess, scenario, scrub)                    # transcript, difficulty, stage, last assessment, found PII
    async for ev in train_pipeline.stream_turn(state, trace=req.trace):    # SequentialAgent[observer, scammer]
        yield sse(ev)                                             # trace | token | state | message_end | session_end
    await repo.append_train_turn(...)                             # user turn + assessment + scammer turn + state patch
    if terminal: await finish_and_score(...)                      # coach runs on /end or auto 1 turn after terminal
```
Terminal conditions (decided by Observer + server rules): `user_fell` (shared OTP/PIN/CVV/card/UPI PIN, installed remote app, agreed to pay), `user_won` (refused + independently verified or reported/hung up after ≥ 3 turns), `walked_away` (client hang-up), `max_turns` (14 user turns → `neutral`). Server rules override the Observer where deterministic (e.g. any `[OTP]` placeholder sent in an extraction-stage context ⇒ `user_fell`).

## 8. Scoring and progression service (`agents/train/scoring.py`)
Pure functions with 100% unit-test coverage — see `4.agents.md` §3.4 for the formula. Called from `finish_and_score`, which also updates streaks, `weakTactics`, global counters, and returns the belt delta.

Streak rule: a calendar day (user's timezone from `Accept-Language`/`X-TZ` header, default `Asia/Kolkata`) counts if the user ended ≥ 1 Train session or completed ≥ 1 Check/Recover plan. Missing a day resets `current` to 0 (best streak retained).

## 9. Demo mode and resilience
- `DEMO_MODE=record`: every successful model response for Check/Recover/opening/debrief is stored in the cache with its key.
- `DEMO_MODE=cached`: serve from cache when a key hits; **on a cache miss, call the live model**; if the model fails, return the closest scripted fallback (for Train: pre-written scammer lines for the three demo scenarios indexed by stage).
- A `scripts/seed_demo_user.py` creates a demo account with 12 historical sessions so the Dashboard looks alive for judges.
- Model failure policy: retry 2× (jittered), then fall back to `MODEL_FALLBACK`; if still failing return `503 model_busy` with `retryable=true`.
- Per-request deadlines: Observer 6s, Scammer first token 8s / total 30s, Coach 30s, Analyst 25s, Planner 30s.

## 10. Privacy and data handling
- Train transcripts store **scrubbed** text only.
- Check stores: scrubbed ≤ 500-char preview, media metadata (type/size/hash), verdict. **No media bytes persisted.**
- Recover stores: intake (free text scrubbed), plan, step states, chat (scrubbed).
- `DELETE /v1/me/data` removes all subcollections and the profile; returns 204. `GET /v1/me/export` returns JSON.
- Logs never contain message bodies; log lengths, hashes, and categorical fields only.
- `/privacy` page content is documented in the README (what is stored, for how long, how to delete).

## 11. Tests (backend)
- **Unit:** scrubber, scoring, belts/streaks, KB queries, indicators regex, quota, media validation, output filter.
- **Contract:** every endpoint against `SqliteRepo` with a **stub model** (`FakeLlm`) returning deterministic JSON/text; OpenAPI schema snapshot test (fails on unintended contract change).
- **Repo parity:** same test-suite for Firestore emulator (marked `@pytest.mark.emulator`).
- **Agent evals** (real model, `make eval`, not in default CI): see `8.demo-and-qa.md`.
- **Security:** auth required on all `/v1/*`; a user cannot read another user's session (403/404); upload of mismatched mime rejected; oversize rejected; CORS only allow-listed.
- **Load smoke:** 20 concurrent train turns using the stub model → p95 < 300ms excluding model.
