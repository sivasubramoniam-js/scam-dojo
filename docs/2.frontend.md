## 1. Stack

| Concern | Choice |
|---|---|
| Framework | Next.js (latest stable, App Router), React, TypeScript `strict` |
| Output | `output: 'export'` (static). **No server components that need a runtime, no API routes, no `next/image` optimizer** (`images.unoptimized: true`). |
| Styling | Tailwind CSS v4 (CSS-first `@theme` using tokens from design §2) + shadcn/ui primitives (Radix) restyled to tokens |

| Data | TanStack Query for REST; custom `useSSE` hook for streams |
| State | Zustand (small stores: `useUi`, `useTrainStore`) |
| Auth | Firebase JS SDK (Auth only; **no direct Firestore reads from client in v1** — everything via API) |
| Charts | Hand-built SVG (`d3-shape` for paths): Sparkline, TacticRadar, RiskGauge |
| Fonts | `next/font/google`: Anek Latin, Anek Devanagari (+ Anek Tamil lazily) |
| Icons | `lucide-react` + custom SVGs |
| i18n | Light custom provider with JSON dictionaries (static export friendly). Keys in design §9. |
| Share card | `html-to-image` |
| Testing | Vitest + Testing Library (units), Playwright (e2e, mobile + desktop), MSW for mocked API, `@axe-core/playwright` |
| Types | `openapi-typescript` generates `src/lib/api-types.ts` from the FastAPI OpenAPI (`pnpm gen:api`) |

Package manager: `pnpm`. Node LTS.

## 3. App shell and navigation

- `AppShell` renders: top bar (logo, language toggle, theme toggle, avatar menu), content, and navigation.
- **Mobile (< 1024px):** bottom tab bar → Train · Check · Recover · Me (dashboard). Icons + labels always visible; active tab has a filled indicator (not colour only).
- **Desktop (≥ 1024px):** left rail with same four items; content column; right panel slot (used by Trace).
- Route guards: Train/Check/Recover/Dashboard require a Firebase user (guest counts). If none, auto-start **anonymous sign-in silently** and continue (no wall). Home is public.
- Persistent "Need help right now?" link in the avatar menu and footer → `/recover`.
- Language: stored in `localStorage` and synced to the profile (`PATCH /v1/me`). Switch is instant (no reload). Sets `document.documentElement.lang`.
- Theme: `light | dark | system`, stored in `localStorage`; applied via `data-theme` on `<html>` before paint (inline script in layout to avoid flash).

## 4. API client (`lib/api.ts`)

```ts
export async function api<T>(path: string, init: RequestInit & { json?: unknown } = {}): Promise<T> {
  const token = await getIdToken();                     // Firebase ID token (or dev header)
  const res = await fetch(`${API}${path}`, {
    ...init,
    headers: {
      ...(init.json ? { 'Content-Type': 'application/json' } : {}),
      ...(token ? { Authorization: `Bearer ${token}` } : {}),
      'Accept-Language': currentLang(),
      ...init.headers,
    },
    body: init.json ? JSON.stringify(init.json) : init.body,
  });
  if (!res.ok) throw await toApiError(res);             // { code, message, retryable, status }
  return res.json() as Promise<T>;
}
```
- Map backend `error.code` → localized message keys (`error.rate`, `error.network`, `error.model_busy`, `error.invalid_file`, …). Never show raw stack text.
- Retry GETs once on network failure. **Never auto-retry POSTs that create sessions.**
- Refresh the ID token on 401 once, then surface a "Sign in again" state.

### SSE client (`lib/sse.ts`)
`EventSource` cannot POST or set headers, so implement a small reader on `fetch`:

```ts
export async function* sse(path: string, body: unknown, signal?: AbortSignal) {
  const res = await fetchWithAuth(path, { method: 'POST', body: JSON.stringify(body),
    headers: { 'Content-Type': 'application/json', Accept: 'text/event-stream' }, signal });
  if (!res.ok || !res.body) throw await toApiError(res);
  const reader = res.body.pipeThrough(new TextDecoderStream()).getReader();
  let buf = '';
  for (;;) {
    const { value, done } = await reader.read();
    if (done) break;
    buf += value;
    let i;
    while ((i = buf.indexOf('\n\n')) >= 0) {
      const raw = buf.slice(0, i); buf = buf.slice(i + 2);
      const ev = /^event: (.+)$/m.exec(raw)?.[1] ?? 'message';
      const data = /^data: (.+)$/m.exec(raw)?.[1];
      if (data) yield { event: ev, data: JSON.parse(data) };
    }
  }
}
```
- Abort on unmount / hang-up.
- If the stream fails before the first `token`, fall back **once** to `?stream=false` JSON variant (all stream endpoints support it; see API contract).
- For multipart uploads (Check), use `fetch` with `FormData` and read the SSE response the same way (response body is SSE even though the request is multipart).

## 5. Auth (`lib/firebase.ts`, `hooks/useAuth`)

- `signInAnonymously()` on first protected-route visit or `/demo`.
- `signInWithPopup(GoogleAuthProvider)`; on mobile prefer `signInWithRedirect` (feature-detect).
- **Link, don't replace:** if the current user is anonymous, call `linkWithPopup`/`linkWithRedirect` with Google so history is kept. Handle `auth/credential-already-in-use` by offering "Sign in to your existing account" (history of the guest is then discarded; show a confirm dialog explaining this).
- `useAuth()` exposes `{ user, status: 'loading'|'signedOut'|'guest'|'signedIn', signInGoogle, signOut }`.
- After sign-in, call `GET /v1/me` to bootstrap the profile (creates it server-side).

## 6. PII safety on the client (`lib/pii.ts`)

Scrub before sending (the server scrubs again, authoritative). The result is shown in the user's bubble and a `PiiNotice` appears once per session.

Patterns (document them in code with tests):
- Aadhaar: `\b[2-9]\d{3}\s?\d{4}\s?\d{4}\b` → `[AADHAAR]`
- PAN: `\b[A-Z]{5}\d{4}[A-Z]\b` → `[PAN]`
- Card: 13–19 digits (spaces/dashes allowed) passing **Luhn** → `[CARD]`
- Indian mobile: `\b(?:\+?91[\s-]?)?[6-9]\d{9}\b` → `[PHONE]`
- UPI ID: `\b[\w.\-]{2,}@[a-z]{2,}\b` (excluding emails with dots in domain) → `[UPI]`
- **OTP/PIN**: a standalone 4–8 digit number *within 40 chars after* a word like otp/code/pin/cvv/पिन/ओटीपी → `[OTP]` / `[PIN]` / `[CVV]`. (In Train mode these placeholders are exactly what the Observer uses to detect "leaked an OTP". The UI shows the user's original masked as `••••` plus the label.)

Never send or store un-scrubbed text in Train mode. In Check mode, scrubbing applies to stored previews only (the analyst needs the original message content to judge; instruct the user not to include their own sensitive data, and the backend removes it before persistence).

## 7. Screens: behaviour spec

### 7.1 Home `/`
- Signed out: `HeroSms` + `ModeTiles` + short "How it works" (3 steps: practice, check, recover) — each step *is* a mode tile, don't duplicate.
- `HeroSms` state machine: `idle → typing → choices → outcome(tap|ignore|check)`.
  - `tap` → outcome text `hero.result.tap` + CTA "Start practice" → `/train` with the Fake KYC scenario preselected (or `/demo` flow).
  - `ignore` → "Good instinct. Want to see how scammers react when you ignore them?" → `/train`.
  - `check` → "Smart. Paste any message you doubt." → `/check` with the hero SMS prefilled.
- Signed in: `BeltSummary` (belt, score, streak, next drill) replaces the hero.
- Skeleton for belt summary while `/v1/dashboard` loads.

### 7.2 Train picker `/train`
- `GET /v1/scenarios?lang=` → cards (title, blurb, channel, difficulty dots, est. minutes, lock state with required belt, "Custom" badge for Forge-made scenarios).
- Difficulty selector appears after choosing a card: **Auto (recommended)** | 1–5. Auto uses the backend's recommendation.
- `PiiNotice` banner always visible on this page.
- Start → `POST /v1/train/sessions` → navigate to `/train/play?sid=…`. The response contains the opening scammer message; render it immediately.

### 7.3 Train stage `/train/play?sid=`
`useTrainSession(sid)` holds: `messages[]`, `status`, `tension (0–10)`, `turn`, `pending` (bool), `streamingText`.

Flow per user send:
1. Scrub text → append user bubble (optimistic) → set `pending`.
2. `sse('/v1/train/sessions/{sid}/messages', {text})`.
3. Events: `token` → append to streaming bubble; `state` → update `tension`, `turn`, `status`; `trace` → push to trace store; `message_end` → finalise bubble; `session_end` → set `status='ended'` with `outcome`; navigate to debrief after 1.2s (show "Sensei is reviewing…" interstitial); `error` → inline error bubble with Retry (re-sends the same text with the same `client_msg_id` for idempotency).
4. Composer disabled while `pending`; Enter sends, Shift+Enter newline; 500 char limit with counter.
- **Hang up / Leave** → confirm sheet ("Walking away is a valid move. End and see your debrief?") → `POST /v1/train/sessions/{sid}/end` → debrief.
- Resume: on mount, `GET /v1/train/sessions/{sid}` and rebuild from stored messages if page reloads. If `status != active` → redirect to debrief.
- `QuickReplies`: optional chips shown after turn 2 ("I'd hang up", "I'd call my bank", "Why do you need this?"). They only fill the composer; user must press Send. A setting "Hide hints" disables them (hints reduce score ceiling slightly? **No** — keep scoring independent of UI hints).
- Auto-scroll to latest unless the user scrolled up; "Jump to latest" pill.
- Idle for 90s → gentle nudge bubble from the Sensei (client-side only): "Still there? You can reply or hang up."

### 7.4 Debrief `/train/debrief?sid=`
- If `debrief` not ready: call `POST /v1/train/sessions/{sid}/end` (idempotent) and show `Sensei is reviewing…` with 3 rotating lines (not generic spinners): "Replaying the conversation", "Marking where pressure landed", "Choosing your next drill". Timeout 25s → error state with Retry.
- Layout per design §6.5. Order: headline sentence → score + belt (orchestrated moment #2) → replay list → tactics bars → three lessons → CTAs.
- `ReplayItem` expands to show "A stronger reply". First item expanded by default.
- CTAs: "Try again" (same scenario), "Try a harder drill" (next recommended), "Dashboard".
- If belt changed: a one-time belt-up sheet with the new belt and a "Share my belt" option (simple image, no PII).

### 7.5 Check `/check`
- Text area (max 5,000 chars) + `UploadDropzone` (accept `image/png,jpeg,webp`, `video/mp4,webm` ≤ 30s/20MB, `audio/mpeg,mp4,wav,ogg,webm` ≤ 2 min/10MB). Validate size/type/duration client-side (read video/audio duration via a hidden media element) and show specific errors.
- Mobile: dropzone label "Add from gallery or camera" (`capture` not forced).
- Client downscales images to max 1600px long edge (canvas, JPEG 0.85) before upload to cut latency.
- Submit → `POST /v1/check` (multipart). Stream events: `stage` (`extracting`, `matching`, `analysing`) drive `AnalyzingSteps`; `result` → verdict; `trace` → trace store.
- Result screen: `VerdictCard` (gauge + verdict + one-line summary), `HighlightedText` (if text present), `RedFlagItem` list, "Do now" / "Don't do" lists, resources (if `already_acted` hint), CTAs: **Share a warning card**, **Train me on this** (`POST /v1/check/{cid}/to-drill` → picker with the new custom scenario preselected), **I already clicked or paid** → `/recover` prefilled with `scam_type`.
- Uncertain verdict (`cannot_tell`) shows what extra info would help ("Add the sender or the full link").
- History: last 5 checks below the form (collapsed).

### 7.6 Recover wizard `/recover`
- `StepWizard` with progress, Back, and per-step validation. Answers saved to `sessionStorage` (so a refresh doesn't lose them).
- On finish: `POST /v1/recover/plans` (SSE with `stage` events: `reading`, `selecting_resources`, `planning`) → navigate to `/recover/plan?pid=`.
- Prefill from Check (`?from_check=cid` → scam type, time = "Just now").
- **If the user says "just now/within 1 hour" and money was sent:** show an **urgent banner at the very top** with the single most important action (call 1930 / call bank) *before* anything else, even before the wizard finishes: "If money left your account in the last hour, call 1930 now." (Static copy from i18n + `tel:` link.)

### 7.7 Recovery plan `/recover/plan?pid=`
- Sections from the plan phases (`now`, `today`, `this_week`, `protect_next`). Each `ChecklistStep`: title, why, how-to (collapsible), optional `ResourceCard` (name, phone/URL, hours if known, "verified on" date), optional `CopyBlock` (draft text: bank message, portal narrative), checkbox.
- Toggle → `PATCH /v1/recover/plans/{pid}/steps/{stepId}` (optimistic; revert + toast on failure).
- Progress ring: "3 of 8 done".
- `RecoveryChatSheet`: SSE chat (`/v1/recover/plans/{pid}/chat`), suggestions chips ("What if my bank won't help?", "Will I get my money back?"). Responses grounded in plan + resources.
- Footer: `disclaimer.legal` + "Contacts verified {date}" from resources.
- `tel:` links on mobile; `mailto:` not used (copy drafts instead).

### 7.8 Dashboard `/dashboard`
- `GET /v1/dashboard`. Components per design §6.10. Empty state when 0 sessions: "No drills yet…" with CTA.
- `Sparkline` supports hover/focus tooltips and has a visually hidden data table for screen readers.
- `TacticRadar` also renders as a sortable list on mobile < 360px.
- History list filter chips: All · Train · Check · Recover. Rows link to their result screens.
- Settings entry (language, theme, delete my data → `DELETE /v1/me/data` with confirm dialog, export JSON).

### 7.9 Demo `/demo`
- One screen: "Take the hot seat." Button → anonymous sign-in → creates a **UPI refund** Train session at difficulty 3 with `trace=1` enabled and the `TracePanel` open on desktop.
- Shows a small facilitator rail: "Reply as you normally would. Walk away any time."
- Query flags: `?lang=hi`, `?scenario=fake_kyc`, `?mode=cached` (backend demo cache, see backend §9).

## 9. Performance budget

- First load JS ≤ 180KB gz on Home; route-level code split for charts, html-to-image, trace panel.
- LCP < 2.5s on simulated mid-range Android over Fast 3G/4G; use font `preload` only for the active script; `font-display: swap`.
- Images: none except icons/og; SVG inline.
- Prefetch the picker and `/v1/scenarios` on Home idle.
- Cache `GET /v1/scenarios` and `/v1/resources` in TanStack Query for 1h.

## 10. PWA (SHOULD)
`manifest.webmanifest` (name, short_name "Scam Dojo", icons 192/512 maskable, theme colour `#16224A`, display `standalone`, start_url `/?source=pwa`). Minimal service worker: cache the app shell + fonts only; **never cache API responses**. Show an "Install" button after the second visit if `beforeinstallprompt` fires.

## 11. Error, empty, loading policy
- Every query/mutation has all four states. Provide `<QueryBoundary>` helper.
- Stream failures after partial output keep the partial text and add an inline "Connection dropped" row with Retry.
- Global error boundary → `ErrorState` with a "Reload" button and a "Report a problem" mailto-free copy-diagnostics button (copies request ID).
- Show `x-request-id` from API errors in a small "Details" disclosure.
